Throughput (messages per second, 5 s average)

Accepted measurements per second, from the change of the counter over the last five seconds (the generator sends one burst per second, so single readings would jump between 0 and 2,000). The generator sends 1,000 per second in steady state.

Latency per message (seconds)

Time from the event time of a message (the camera) to its processing: average (dark) and maximum (light) over the last 10 seconds. Flat when the processor keeps up; it rises when it falls behind. The scale follows the data; the red line (the warning threshold) appears when the values get near it.

Age of the newest event (seconds)

Wall-clock time minus the event time of the newest processed measurement (the former "ingest lag"). It saw-tooths from 0 to the tick interval between the generator bursts by design, and grows without bound when nothing arrives (the boards are frozen); the client uses it for "live". Read the latency chart for the real delay.

Ingest buffer (items)

Items waiting in the processor's own ingest queues (one per partition, bounded), between the MQTT receive and the workers. It is not the broker's queue: when it is full the processor stops acknowledging and the broker holds the messages. It usually stays near zero: the MQTT receive path (decode, submit, acknowledge one message at a time) is slower than the workers, so a lag that grows while this buffer is empty means the backlog waits in the broker. The scale follows the data; the red line (total capacity) appears when the queue gets near it.

Tracked vehicles

Vehicles that are on the road (a vehicle track exists). About 900 in steady state at 100 new vehicles per second, ten seconds per passage.
